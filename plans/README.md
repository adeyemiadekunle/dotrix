## Findings considered and rejected

- "Dead" per-provider API-key settings in `core/settings.py`: not established — `core/model_providers.py` still references those field names, so removal needs its own investigation.
- Admin console offset paging can shift rows between pages: tolerable for an operator console.
- Unsigned desktop updates: documented as intentional for now.
- Routers querying the database directly: one instance (`agents/router.py:196`), not a pattern.
- Backend `safe_next_path` being weaker than the web's check: not exploitable (redirects are percent-encoded).
- The four parked browser specs (`test.fixme`), the size of `Settings.tsx` / `Chat.tsx`, and the store-to-Query migration: already on the maintainer's roadmap in `CLAUDE.md`.
- Checked and found sound: GitHub webhook signature verification, the rate limiter and trusted-proxy handling, avatar and attachment serving, the web's Markdown and confirm-dialog HTML escaping, workspace and privacy checks on the project, run and coding routes sampled, the Docker egress proxy's host matching, archive extraction.
